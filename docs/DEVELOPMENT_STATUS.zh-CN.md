# HomePodCast 当前版本状态

更新：2026-11-02。按现有 VB-CABLE 集成方案收尾，暂缓单端点品牌驱动。当前为开发预览，不创建正式发布标签。

## 本版功能

- 实验性 `HomePodCast-Setup.exe` 包含应用及未经修改的标准 VB-CABLE Pack45，无需用户另行下载驱动。配置向导仍会显示原厂安装界面并请求管理员确认；安装驱动后需要重启并再次运行配置向导。
- 已安装的可用 VB-CABLE 直接复用。卸载后只有服务残留时允许交互式安装；设备异常、查询失败或设备在安装前重新出现时停止，避免误进入卸载流程。
- 虚拟模式捕获选定输出，可在串流就绪后自动切换 Windows 默认输出，并在停止时有条件恢复。通信设备单独选择是否切换。
- 电脑输出和虚拟输出有不同列表与说明；失效的已保存设备不会被静默替换。应用的“音箱音量”控制 HomePod，Windows 音量控制当前默认输出。
- 虚拟采集在静音或音量为 0 时清零 PCM，非零音量保持采集值，避免重复衰减。
- 应用更新只接受 `HomePodCast.exe`，不会把安装包误当成应用替换。固定与 pyatv 兼容的 SRP 依赖，自检覆盖离线认证与加密路径。
- 安装器校验第三方包哈希、厂商签名、微软目录签名及 INF/SYS 的目录关联；卸载应用保留共享 VB-CABLE。

## 明确保留的限制

- 标准 VB-CABLE 在 Windows 中仍显示原名称和两个播放端点。应用列表优先显示标准 CABLE Input；本版不禁用或重命名 Windows 设备。
- VB-CABLE 控制面板须启用 **Enable Windows Volume Control**，Windows 1–100 音量才能作用于已测采集路径。Windows 默认输出需与选择的音源一致；录音端的“侦听此设备”应关闭。
- 应用和安装器目前没有生产代码签名；Smart App Control 可能拦截。不会为此关闭系统保护。VB-CABLE 驱动签名不代表外层应用获得信任。
- 自有 `HomePodCast Audio` 驱动仅为测试签名原型，不随安装包安装；虚拟机 PCM 已做过探测，原生静音、正式签名和完整兼容性验收仍未完成。
- 两小时长测按用户要求暂缓；本次不重复安装驱动、重启系统或声称完成新装系统、所有 Windows 版本、休眠和多 HomePod 断线矩阵验收。
